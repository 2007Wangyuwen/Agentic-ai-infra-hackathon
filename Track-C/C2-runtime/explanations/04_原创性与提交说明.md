# 原创性、依赖与提交说明

本文档用于解释本提交如何满足竞赛规则，以及最终应该提交哪些文件。

## 1. 原创性说明

本提交是在 C2 官方 starter kit 的公开契约之上完成的实现。

自行实现的文件包括：

```text
src/aec_runtime.cpp
agents/dma_agent.py
agents/kernel_agent.py
```

官方文件作为 ABI、ISA、数值规范和本地验证工具使用，包括：

```text
include/
lib/libaec_device.so
kernels/
schemas/
grader/
cases/
examples/
docs/
```

正式提交时不应把官方设备库、官方头文件、kernel image、grader 或公开测试作为自己的提交物。

## 2. 第三方依赖

本实现没有引入额外第三方库。

Runtime 使用：

- C++17 标准库。
- 官方 `aec_runtime.h`。
- 官方 `aec_device_abi.h`。

Agent 使用：

- Python 标准库 `json`。
- Python 标准库 `math`。
- Python 标准库 `sys`。

## 3. AI 辅助披露

开发过程中使用了大语言模型辅助：

- 阅读和总结赛题文档。
- 规划 Runtime 实现顺序。
- 编写和检查代码。

队伍应能解释和维护最终代码。核心逻辑都来自 C2 官方文档中的 Runtime API、Device ABI、数值规范、Agent schema 和评分要求。

## 4. 不硬编码说明

本提交没有根据以下信息做分支：

- 公开测试 case 名。
- 隐藏测试标识。
- 输入 hash。
- 固定输入数据。
- 文件名。
- `test_rXXX` 名称。

Runtime 的判断依据是 API 参数和 Runtime 生命周期状态。

DMA Agent 的判断依据是：

- `bytes`
- `alignment`
- `registered`
- `concurrency`

Kernel Agent 的判断依据是：

- `m/n/k`
- `alignment`
- `workspace`
- candidate 的 `workspace/alignment/divisibility/variant`
- candidate 中可选的 `diagnostic_cycles`



## 5. 不绕过评测说明

Runtime 的计算接口不在 Host 侧直接生成计算结果。

所有成功的计算接口都会走：

```text
Runtime API
-> canonical 参数块
-> aecDeviceResolveKernel
-> AEC_DEVICE_OP_ISA_LAUNCH
-> aecDeviceSubmit
-> 官方虚拟设备执行 fixed image
```

这满足 C2 对 fixed image、retired instructions、trace digest 和 kernel handle 的检查要求。

## 8. 重建提交目录

```bash
rm -rf submission
mkdir -p submission/agents
cp libaec.so submission/
cp agents/dma_agent.py submission/agents/
cp agents/kernel_agent.py submission/agents/
```

检查：

```bash
find submission -type f -print | sort
```

应输出：

```text
submission/agents/dma_agent.py
submission/agents/kernel_agent.py
submission/libaec.so
```



## 9. 本地验证提交目录

因为 `submission/libaec.so` 运行时需要官方设备库，所以本地验证时需要：

```bash
LD_LIBRARY_PATH=$PWD/lib python3 grader/public_grade.py --submission submission --profile public
```

如果不设置 `LD_LIBRARY_PATH`，可能出现：

```text
libaec_device.so: cannot open shared object file
```

这只是本地动态链接路径问题，不代表正式提交目录缺文件。正式评测环境会提供官方设备库。
